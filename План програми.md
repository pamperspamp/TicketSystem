# План програми «Система обліку та продажу квитків на заходи»

## Що будуємо

Настільну програму для касира невеликого закладу, де проходять вистави, концерти й кінопокази. Касир обирає показ в афіші, бачить схему зали, бронює або продає місце та видає код квитка. На вході за цим кодом можна перевірити квиток і зареєструвати відвідування.

У проєкті вже є головне вікно Qt Widgets, таблиця подій та оформлення. Починаємо з наявної форми. План розрахований на одну локальну касу. Продаж означає запис про отриману оплату й видачу квитка.

## Які екрани додати

| Екран | Що бачить користувач | Що може зробити |
|---|---|---|
| Афіша | Назву, тип, дату, час, залу та ціну кожного показу | Відкрити показ, додати новий, змінити дані або видалити показ без операцій |
| Зала | План місць за рядами, легенду станів і лічильники | Вибрати місце, забронювати, скасувати бронь, продати вільне або викупити заброньоване |
| Оформлений квиток | Назву показу, дату, залу, ряд, місце, сплачену суму й унікальний код | Скопіювати код або повернутися до зали |
| Контроль входу | Вибраний показ і поле для коду | Перевірити квиток і зареєструвати один прохід |
| Звіт за показом | Кількість місць, броней, продажів, проходів та виручку | Побачити результат роботи каси |

## Куди писати код

| Файл або клас | Відповідальність |
|---|---|
| mainwindow.ui | Розміщення таблиці, кнопок і сторінок у Qt Designer |
| mainwindow.h і mainwindow.cpp | Зберігати ID відкритого показу, реагувати на натискання, передавати команду сервісу, оновлювати екран |
| event.h, seat.h і ticket.h | Структури Event, Seat і Ticket описують дані одного показу, місця й квитка. Для станів броні, продажу та скасування використати enum class |
| database.h і database.cpp | Клас Database відкриває файл SQLite, створює таблиці та читає дані афіші й зали |
| ticketservice.h і ticketservice.cpp | Клас TicketService реалізує правила бронювання, скасування, продажу й контролю входу. Він отримує підключення до БД і повертає результат операції |
| main.cpp | Створити підключення та сервіс на час роботи програми, передати їх головному вікну |
| CMakeLists.txt | Підключити Qt Sql і додавати нові файли до PROJECT_SOURCES |

У Qt Creator обери проєкт course → Add New → C++ Class. Наприклад, для TicketService майстер створить заголовок і файл реалізації. У заголовку оголошуєш доступні дії, у файлі .cpp пишеш їхні тіла. Наприклад, після натискання «Забронювати» головне вікно передає eventId і seatId у reserveSeat(). Сервіс записує бронь, а вікно після успіху перечитує стан зали. Так той самий метод можна перевірити окремо від кнопки.

## Як зберігати дані в SQLite

| Таблиця | Основні поля |
|---|---|
| halls | id, назва зали |
| seats | id, hall_id, ряд, місце. Комбінація зали, ряду й місця унікальна |
| events | id, назва, тип, дата й час початку, hall_id, ціна в копійках. Один запис відповідає одному конкретному показу |
| tickets | id, event_id, seat_id, стан, ім’я для броні, унікальний код проданого квитка, сплачена сума в копійках, час продажу, час проходу |

Увімкнути зовнішні ключі для підключення. Додати частковий унікальний індекс на пару (event_id, seat_id) для станів «бронь» і «продано». Скасована бронь залишається в історії та звільняє місце. Перед кожною операцією перевіряти, що місце належить залі вибраного показу. Гроші зберігати цілими копійками. Виручку рахувати за сумою, зафіксованою в момент продажу.

## Порядок реалізації

| Етап | Що зробити | Як перевірити |
|---|---|---|
| 1. Підключити SQLite | Додати Sql поряд із Widgets в обидва find_package та Qt Sql у target_link_libraries. У Database відкрити tickets.db через QSQLITE в папці даних застосунку. При першому запуску створити таблиці та початкові приклади | Після двох запусків кількість подій однакова. При помилці відкриття з’являється зрозуміле повідомлення |
| 2. Вивести афішу з БД | Прибрати приклади з форми після того, як запрацює читання. Заповнювати таблицю з результату запиту. Зберігати ID показу в Qt::UserRole | Два покази з однаковою назвою, але різним часом відкриваються правильно навіть після сортування |
| 3. Додати навігацію і план зали | У Designer додати QStackedWidget зі сторінками афіші, зали та контролю входу. Подвійне натискання на показ передає його ID та відкриває сторінку зали. Побудувати кнопки місць у QGridLayout | «Назад» повертає до афіші. На двох показах в одній залі той самий номер місця може мати різний стан |
| 4. Реалізувати бронювання | Для вільного місця відкрити короткий діалог з іменем, записати бронь. Скасування дозволити лише для чинної броні. Показувати стан місця текстом і кольором | Подвійний клік не створює дві броні. Після перезапуску бронь зберігається, після скасування місце знову доступне |
| 5. Оформити продаж | Вільне місце можна продати відразу. При викупі оновити наявну бронь. В одній транзакції записати продаж, ціну й унікальний код. Показати квиток після успішного збереження | Повторний продаж відхиляється. Викуп броні збільшує продажі на один і зменшує броні на один |
| 6. Перевіряти квитки | Для вибраного показу приймати код. Одним умовним UPDATE записувати час входу, лише якщо квиток продано й ще не використано. Перевіряти кількість оновлених рядків | Перший прохід дозволено, другий дає «Уже використано». Окремо перевірити чужий показ і невідомий код |
| 7. Додати керування афішею і звіт | Створити форму додавання та редагування показу. Перевіряти назву, залу, ціну й час. Для показу з квитками заборонити видалення або зміну зали. Підсумки отримувати запитом за ID показу | Новий показ є в афіші після перезапуску. Спроба видалити показ із продажами зберігає його історію. Суми у звіті збігаються з квитками |

## Як рахувати заповненість

Для вибраного показу взяти кількість місць його зали. Вільні місця = усі місця − чинні броні − продані квитки. Відсоток зайнятих місць = (броні + продажі) × 100 / кількість місць. Для порожньої зали показати «Місця не налаштовані». Кількість людей, які вже увійшли, визначати окремо за часом проходу.

Контрольний приклад для зали на 10 місць. Забронюй два місця та продай третє за 250 грн. Очікувано вільних 7, броней 2, проданих 1, виручка 250 грн. Викуп однієї броні за 250 грн дає 7 вільних, 1 бронь, 2 продажі та 500 грн виручки. Перевірка одного квитка на вході додає одне відвідування.

## Що показати на захисті

Створити показ, відкрити залу, забронювати місце, викупити бронь і скопіювати код. Перезапустити програму, перевірити цей код двічі та відкрити звіт. У тексті курсової цей сценарій можна проілюструвати схемою таблиць SQLite, діаграмою класів та знімками афіші, зали й результату перевірки.

Почни з етапів 1 і 2. Перший робочий результат — знайома афіша, яка читає три події з файлу tickets.db.
